# V7.3 Fix Notes

Build: `7.3.0-20260810`

## Numeric Result Recognition Engine

V7.3 is focused on OCR digit accuracy after V7.2 proved that the Result-cell geometry is correctly located.

### Changes
- Result-cell crop remains the primary source of truth.
- Added tight-center crop passes after rule-line removal.
- Added PSM 10 in addition to line/word/raw OCR modes.
- OCR whitelist is numeric-only: `0123456789.`.
- Added decimal-format hints by test type (HbA1c, creatinine, uric acid, Hb, Hct, WBC, PSA).
- Can recover a dropped decimal point from a numeric token when the test format supports it.
- Can trim a likely extra trailing OCR glyph when the reported precision is known.
- Strongly penalizes one-digit truncation when a fuller plausible token appears in another pass.
- Reference ranges are used only to rank plausibility, not to invent patient values.
- All imported OCR values remain manually reviewable and are not auto-selected.

### Regression targets from the supplied health report
The engine is intended to correctly preserve numeric forms such as `5.5`, `0.461`, `222`, `47.2`, `15.8`, `6.91`, `20`, `158`, and `59` when those values are actually visible in the Result cell. These are test targets, not hard-coded patient-result substitutions.
